### Correction to C2 — the gate did not go red, it was **inert**

C2 predicted the next `EVAL_REQUIRE_ALL=1` run would "very likely go **RED**". **It did not.** The push
run for the eval-revert merge went **green**:

- Run `29767229051` — `event: push`, `headSha: a35c13d`, `conclusion: success`.
- Nightly runs (`schedule`, `c1e728f`) also `success`.

C2's regression *math* is still correct (Small ≈ 0.835 < the 0.85 absolute floor; Large baseline floors
at 0.921/0.863). What was wrong is the assumption that Gate C would *run*. It didn't — for two
independent reasons, both discovered post-review:

1. **Turbo strips the enforcement flag.** Turbo v2 runs in **strict environment mode** by default and
   filters out every env var a task doesn't declare. The `test` task in `turbo.json` declared only
   `SCALEWAY_API_KEY` + `MISTRAL_API_KEY`, so `EVAL_REQUIRE_ALL` (set on the *job* in `ci.yml:79`) never
   reached the eval process → `REQUIRE_ALL` resolved to `false` → a missing-key gate **skipped and
   passed** instead of failing. Same for `DATABASE_URL`, `EVAL_REQUIRE_DB`, `EVAL_JUDGE_SAMPLES`,
   `GITHUB_SHA`.
2. **The credentials are absent anyway.** CI logs show `SCALEWAY_API_KEY not set` — the repo secrets are
   empty, so Gate B/C had nothing to run with even before the flag was stripped.

**Revised severity: higher than C2 implied.** The merge gate was not "about to catch" the regression —
it was structurally incapable of catching it. A green `verify` on `main` currently certifies only
Gate A + the D-contract; Gate B/B2/C/F have never actually run in CI. This is the true root of C1's
symptom set.

**Fix (implemented):** `turbo.json` `test` task now declares all eval control + credential vars in
`passThroughEnv` and sets `"cache": false` (a live eval must never replay a cached pass). The coupling
invariant is enforced offline by `packages/agents/src/evals/eval-model-coupling.test.ts` and documented
in `docs/eval/GATE-ARCHITECTURE.md`. **Remaining ops action (cannot be done from code): add
`SCALEWAY_API_KEY` and `MISTRAL_API_KEY` as GitHub Actions secrets.** Until then, with the turbo fix in
place, push/merge runs will now correctly go **RED** (required-but-unavailable) instead of green.

pair; neither alone is a lock. See `docs/eval/GATE-ARCHITECTURE.md` (Invariant 2).
